# 城市化审批修订实施计划

**目标：** 按最新提示词完善城市化与审批流程，解释空候选原因，保持服务端授权和正式文件隔离。

**架构：** 继续复用 `ApplyUrbanAreaCommand`、`ApprovalManager` 与现有临时顶点编辑、TCP、边界可视化。`submit_urban_area` 默认关闭，`type` 缺省视为 `rural`，成功城市化写入 `urban`；普通玩家按域名主署名 `signature` 精确匹配玩家名，等级至少为 2 的 OP 直接处理。额外署名 `signatures` 和上级域名的署名不参与此项授权。

**技术：** Java 17、Fabric、Stonecutter 多版本构建、Gson。

1. 对照两端日志、服务端配置、OP 和域名数据确认空列表来自归属过滤，按最新要求将城市化归属判断统一为 `signature` 匹配当前玩家；`base-name` 继续只表示上级域名。
2. 在 `urban/ApplyUrbanAreaCommand.java` 分别反馈当前维度没有域名、没有农村域名、没有符合归属规则的域名，并记录查询维度、服务端文件和候选数以便定位。
3. 在 `AreaData`、JSON 转换及新建/几何复制入口保留缺省类型；审批内部继续规范化比较，写回正式文件时不为缺省农村域名强制增加字段。
4. 在客户端审批详情明确展示审批人、类型、结果和可阅读的意见；打回后进入单独的编辑状态，保留特殊 addhint/deletehint、重新申请及全部历史。
5. 修复删除申请预览仍绘制删除前域名的问题，保持 TCP 使用删除前坐标定位、长按恢复面板。
6. 核查全局申请、对应世界回复缓存、在线与离线同步、正式写入事务、LuckPerms 和 GUI 命令可见性，复用已满足要求的实现。
7. 更新全部 11 种语言及命令文档；执行编译打包、JSON/占位符/差异检查和独立代码复核，不新增测试代码；游戏内由用户测试。
8. 直接在 `main` 修改，不创建 worktree；按最新明确授权提交本次实现，保留用户已有的 `forth-prompt.txt` 修改。
