## 三、三档划分（Task 1 Step 3）

| 档位 | 版本 | 判定理由 |
|---|---|---|
| **必出包** | **1.20.4**（常驻基线）、**1.20.1**、**1.21.1** | 官方依赖与第三方依赖 100% 齐；1.20.1 与基线同代际（Yarn/Java 17/网络 API 同形态，实测 src/main 0 错误）；1.21.1 是当前玩家基数最大的近版本 |
| **仅声明** | **1.20.6**、**1.21.4**、**1.21.5**、**1.21.8**、**1.21.11** | 依赖 100% 齐，但都要先过 NetworkCompat（1.20.6）或渲染层适配（1.21.x）；**在阶段 3、4 完成前不进 `versions()`** |
| **实验性** | **26.1**、**26.2** | 无 Yarn、无 intermediary、需要 JDK 25 与 no-remap Loom；VulkanMod 也无坐标；第三方只覆盖 Xaero/ModMenu/BlueMap |

**本阶段不新增任何编译目标**：`versions()` 仍是 `'1.20.4', '1.21.1'`。按验收口径「不能编译的版本不要留在 `versions()` 里」，1.20.1（16 处客户端错误）与 1.20.6（61 条网络层错误）现在都不能进。

## 四、Java 工具链：需要 3 套（17 / 21 / 25）

| Java | 版本 | 本机现状 |
|---|---|---|
| 17 | 1.20.1、1.20.4 | `C:\Program Files\Java\jdk-17` ✓（当前节点实际用 JDK 21 + `options.release=17` 编译，产物与基线一致，**不要动**） |
| 21 | 1.20.6 – 1.21.11 | `JAVA_HOME` = `jdk-21` ✓ |
| 25 | 26.1、26.2 | 本机未装 JDK 25，但 Gradle 已缓存 toolchain `eclipse_adoptium-25-amd64-windows.2` ✓（启用 toolchain 后可用） |

**注意**：26.x 与 1.21.x 的第三方 jar 也是按 Java 版本编的（Xaero 26.x = class major 69 = Java 25；1.20.6–1.21.11 = 65 = Java 21）。节点工具链低于依赖的字节码版本会直接编译失败，所以「按版本对齐 Java」不是可选项。

## 五、坐标取舍：三处必须知道的坑

1. **Xaero 换过命名规则**（关键）。旧格式 `<模组版本>_Fabric_<MC版本>` 止于 2025-12-31 的 `25.3.2`/`1.40.2`，之后是 `fabric-<MC版本>-<模组版本>`。
   - 本表 1.20.1–1.21.11 **故意选旧格式世代**（`25.3.2_*` / `1.40.2_*`）：与基线 25.2.0/1.39.2 只差 1~3 个小版本，共享兼容层的 API 漂移最小；1.20.6 只有 `25.2.10`/`1.39.12` 一条线，它决定了共享源码的 API 交集。
   - 26.1/26.2 只有新格式，没有选择。
   - **计划文档 02 第 63 行「MC 版本段必须与目标版本一致」不成立**：1.20.1 的段是 `1.20`、1.21.1 的段是 `1.21`。唯一可靠判据是 Modrinth 的 `game_versions`。
   - 备选（各版本最新 release，如 1.20.1 = `fabric-1.20.1-26.5.0`）见 `research/A-xaero.md` 主表，漂移更大，暂不采用。
2. **BlueMap 改过坐标名**：旧 `de.bluecolored.bluemap:BlueMapAPI` 冻结在 2.7.2（2024-06-03），新坐标 `de.bluecolored:bluemap-api` 到 2.8.1。
   - 且字节码版本不同：2.7.2=JVM16、2.7.3–2.7.8=JVM21、2.8.0+=JVM25 → 必须按节点 Java 选。1.20.x 用 2.7.2，1.20.6–1.21.11 用 2.7.8，26.x 用 2.8.1。
   - 因此 `build.gradle` 里 BlueMap/LuckPerms 改为读**完整坐标**，不再是 `group:artifact:<版本>` 写死。
3. **VulkanMod 的 version_number 跨 MC 重复**：`maven.modrinth:vulkanmod:0.5.6` 实际取到的是 **1.21.4** 的 jar（已实测解包），1.21.5 节点会重演「编译能过、运行时加载失败」→ 要用版本 id（1.21.5 = `7pYvUnJk`）。
   - 但**当前不需要 VulkanMod 编译期依赖**：`VulkanModCompat` 全用反射，源码里没有 `net.vulkanmod` import。上表仅供将来使用。

## 七、不确定项（需你拍板或后续实测）

1. **「26.1」指哪个**：26.1 还是补丁版 26.1.1 / 26.1.2？（Xaero/Fabric API 的坐标都是按 26.1.2 给的）
2. **Xaero 用旧格式世代还是最新 release**：本表选了「漂移最小」的旧格式世代，如果兼容层需要新 API 则要换（两份表都在 `research/A-xaero.md`）。
3. **Loom 插件 id**：`net.fabricmc.fabric-loom`（no-remap，26.x 用）与 `net.fabricmc.fabric-loom-remap`（≤1.21.11）只能靠官方公告佐证，**建议后续真做 26.x 时先探针实测一次**。
4. **1.20.4 是否跟进上游**：Fabric API 有 `0.97.3+1.20.4`、loader 有 0.19.5。换了会动产物，需先决定是否重设 D1 基线。
5. 调研员未跑 gradle（遵守约束），所以「坐标能不能真的被 Loom 解析并编译」尚未实测——本阶段只有 1.20.4 一个节点能验证，其余要等对应阶段。
