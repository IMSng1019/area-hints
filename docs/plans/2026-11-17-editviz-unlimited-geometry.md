# editviz 复杂度限制移除与笔宽滑块

**目标：** 按用户明确要求移除绘制、魔棒、草稿与保存流程中的固定复杂度和顶点数量拒绝条件，并提供可拖动的笔宽滑块。

**架构：** 保留现有几何、权限、草稿历史与保存审批架构。旧版 `src/` 与 `modern/src/` 同步维护；保留世界坐标、有限数值、单环无洞无自交校验。缓存容量和分帧地形读取预算不作为几何拒绝条件；可选简化超过工作预算时保留合法轮廓，不拒绝保存。

**技术：** Java 17/21/25、Java2D Area、Fabric 多版本 GUI、JUnit 5。

## 实施步骤

1. 在两套 `VizEditGeometryTest` 中先验证超过旧顶点、魔棒边数、斜面栅格与笔画路径上限的输入；运行测试确认现有失败，再修改 `VizEditGeometry`、`BlockSnap`、`FenceFaces`、`BoundaryOptimizer`。
2. 移除 `BoundaryBrush` 中累计地形、岸线、偏移记忆与局部计算面积导致的固定拒绝条件；保留异步读取预算、岸线规则及撤销状态。为适用的旧阈值增加回归测试。
3. 移除两套 `VizEditChangeService` 的 JSON 顶点数组数量限制，并验证超过旧保存上限的域名可以完成服务端校验和存储转换。
4. 两套 `VizEditScreen` 使用原生滑块调节 1～256 格笔宽，支持拖动、键盘微调和当前数值显示；正确转发拖动／释放事件，不与画布绘制、平移冲突。移除屏幕层笔画采样数量限制。
5. 更新全部 11 种语言中涉及旧固定限制的文案与命令文档；不压缩翻译文件。运行翻译检查、针对性测试及全部 12 个活跃版本构建。
6. 独立审查变更、处理发现的问题，检查差异后在 main 提交；如未进行游戏内验证，明确记录。

## 大轮廓兼容性处理

JDK 25 的 `Area` 运算可能把连续区域按水平扫描段输出为多个贴边子环。移除旧上限后，大型魔棒填充会暴露这一差异：面积正确，但直接把子环视为独立区域会误判不连通，真实的洞也可能被切成多个外环。

两套几何内核新增 `AreaContours`，统一提取真实轮廓：只精确抵消同一水平线上的正长度反向共享边，再沿原边方向重新连接。保留真实孔洞、仅点接触、不相连区域、任意小缺口与小数斜边；不使用近邻吸附，不修改输入 `Area`。无法完整重接时保留原轮廓交给原有校验。

自交检查复用包围盒树筛选可能相交的边对，画布填充采用活动边扫描。两个优化都保留原几何规则，避免去掉数量上限后继续无条件全量比较。

## 验收

- 大型斜面、超过 4096 条边的魔棒输入、超过 4096／16384 顶点的保存不再因固定数量拒绝。
- 旧版与 modern 一致；无效坐标、自交、洞与不连通仍正确拒绝，失败不破坏草稿。
- 笔宽滑块可以拖动，窗口重建及画布切换保留宽度，调节不会新增笔画或撤销记录。
- 运行检查完成后记录结果；源码直接修改 main，不创建 worktree。
