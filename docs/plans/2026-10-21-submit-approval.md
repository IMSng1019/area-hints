# 服务端配置与域名审批实施计划

**目标：** 新增默认开启的 submit_approval 服务端配置，普通玩家保留现有权限检查，合法修改转为申请，OP 即时修改；支持预览、临时顶点编辑、审批、离线回复与带历史意见的重新申请。

**架构：** 沿用现有世界目录、网络兼容层、录点与边界显示架构。在服务端校验完成而正式数据写入之前建立申请；保存修改前后差异，批准时检查冲突并合并。客户端预览只覆盖内存显示，不写正式域名文件。

**技术：** Java 17、Fabric、Gson、现有 NetworkCompat / ClientNetworkCompat 和 Stonecutter 多版本构建。

1. 新增共享审批模型、服务端配置与持久化管理。全局目录存放配置及带世界标识的申请；缺失配置项取默认 true。
2. 覆盖添加、删除、改名、颜色、高度、顶点、扩展、收缩、划分、签名、副字幕、描述及维度域名的写入入口，保留现有权限。
3. 增加有版本校验的审批网络协议、OP 审核权限、仅本人回复查询、登录同步、离线持久化和审批意见历史。
4. 新增长按菜单入口、列表和详情窗口、回复输入、打回编辑与重新申请。临时 addhint/deletehint 复用原交互，TCP 解析经过服务端授权的临时目标。
5. 对所有语言文件添加对应语言文本，补充功能使用说明。
6. 不新增测试，执行编译、JSON 完整性检查及代码审查；游戏内操作由用户验证。不创建 worktree，不主动 commit。

**主要约束：** OP 身份与 LuckPerms 普通命令权限分开判断；多对象修改必须整体校验；已处理或旧版本申请不能重复批准；断线清理预览；客户端配置缓存不作为服务端授权依据。
