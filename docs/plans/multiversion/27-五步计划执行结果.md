## 三、第 2 步与 1.21.5：为什么停下

1.21.5 实测撞上**渲染管线整代重写**：
- `net.minecraft.client.render.BufferRenderer` **整个类被移除**（两个 1.21.5 命名 jar 里都找不到）；
- 替代路径是 `RenderSystem.getDevice().createCommandEncoder().createRenderPass(...)` + `RenderPass.setPipeline/setVertexBuffer/draw/close`，配合 `GpuBuffer`；
- 同时 `VertexFormat` 从 `net.minecraft.client.render` 移到 `com.mojang.blaze3d.vertex`（这个已修）。

我们的 5 个绘制点（BoundVizRenderer ×3、OverlayRenderHelper ×2）走的是旧立即模式，**无法用几行条件注释替代**，必须实现 RenderPass 版绘制。这正是 22 号文档说的「RenderHost 抽象」要解决的问题，也说明 **1.21.5 / 1.21.8 / 1.21.11 与 26.x 是同一档工作量**。

因此 1.21.5 **已从 `versions()` 移除**（版本目录保留，作为下一步起点），默认构建保持全绿。

- **逐节点版本号**写进各自实现，顺带修掉了原 `XaeroCompat` 硬编码 `25.2.0/1.39.2` 导致非基线节点联动被静默禁用的老问题。

### 一个必须记下的坑（D1 相关）

隔离时把 `XaeroMinimapBridge` 的内嵌类 `TransformState` 抽成了顶层 `MinimapTransformState`，导致基线条目 `areahint/xaero/minimap/XaeroMinimapBridge$TransformState.class` **消失**，`verify-baseline` 直接 FAIL。
处理：在每个节点的 `XaeroMinimapBridge` 里保留一个**兼容嵌套 record**，并在注释里写明「为守住 D1 而保留」。
**另一条实测结论**：`versions/` 下的文件**不经过 Stonecutter 处理**（证据：节点生成目录里全是 `src/` 的文件，版本目录独有的类一个都没有）——所以版本目录里**写条件注释无效**，只能逐节点复制不同实现。

## 五、第 4 步：26.x 探针（完成，结论可行）

详见 `24-26x-no-remap探针.md`。要点：
- **可行**：不重映射的 Loom 能给 26.1.2 编出 jar（产物 1274 B，类字节码 major=69 即 Java 25），走的是 `:jar` 而非 `remapJar`，`net.minecraft.SharedConstants` 这类官方名可直接用——**确实不需要任何映射**；
- **硬约束**：保留 Gradle 9.5.1 就必须用 **Loom ≤ 1.17.21**（1.18.2 要求 api-version 9.7.0 且构建 JVM 25）；
- **坑**：`~/.gradle/jdks` 里的 JDK 25 不会被自动探测，必须显式 `org.gradle.java.installations.paths`，且路径含中文会被按 ISO-8859-1 解析（需 ASCII 路径）；
- **未做**：真正搬代码。26.x 是**不混淆**的，类名包名是 Mojang 官方名，而本仓库全部代码用的是 Yarn 名——搬过去等于**全代码库改名**（26 号文档里已给出 78 个 import / 30 条对照表），属于独立的大工程。
