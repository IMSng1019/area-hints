# 专用服务器域名同步竞态修复设计

## 问题

服务端在玩家加入时立即发送三个维度的域名数据。客户端此时可能尚未取得世界名称，`ClientWorldFolderManager` 会把数据写入备用根目录；随后客户端切换到正式世界目录，`AreaDetector` 又从正式目录加载，因此 Xaero 快照和当前域名检测可能使用两份不同的数据。

## 方案

客户端在正式世界目录初始化完成前不落盘域名数据，而是按维度缓存最近一次收到的内容。缓存与当前 `ClientPlayNetworkHandler` 绑定，旧连接已经排入主线程的任务会在执行前被丢弃。收到世界名称并完成正式目录初始化后，使用原有保存流程依次回放缓存数据，再执行当前维度重新检测。

同时将临时目录状态的建立移动到世界信息请求之前，避免响应到达时客户端仍没有任何目录上下文。断开连接时立即使对应连接缓存失效，其余状态统一排入客户端主线程清理，防止不同服务器之间串用数据。

强制重新检测会先使旧异步检测代次失效，再同步发布 `AreaChangeTracker`。这样 Xaero 在缓存回放完成后即可获得当前实际域名，旧目录产生的异步结果也不能覆盖新状态。

## 数据流

1. 服务端发送 `S2C_AREA_DATA`。
2. 客户端目录未完成初始化时，将 `dimension -> fileContent` 保存到内存。
3. 客户端收到世界名称并完成正式目录初始化。
4. 世界信息和域名数据任务校验自身仍属于当前网络连接。
5. 缓存内容通过原有文件保存、Xaero 快照刷新、当前维度检测器加载和 BoundViz 重载流程处理。
6. 回放完成后使旧异步结果失效，并同步发布一次当前区域检测状态。

## 兼容性

- 不修改网络包标识、字段或服务端协议。
- 目录已经初始化时仍立即处理数据，运行中的域名增删改行为不变。
- 同一维度在初始化前收到多次更新时只保留最新内容，避免旧数据覆盖新数据。
- 未知维度在进入缓存前被拒绝，缓存大小限定为模组支持的三个维度。
- 不修改域名 JSON 格式、Xaero 渲染算法、配置或翻译。
