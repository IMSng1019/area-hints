# 2026-11-16 可选模组联动检查

检查范围：Fabric 1.20.1、1.20.4、1.20.6、1.21.1、1.21.4、1.21.5、1.21.8、1.21.10、1.21.11、26.1.2、26.2、26.3，共 12 个构建目标。

## Xaero 联动

根因与修复：

- 全部目标原先使用版本号完全相等的准入条件，同一 Minecraft 的地图更新也被直接禁用。现在按实际接口装配，两张地图各自处理失败；初始化检查失败不再记录成功日志，元数据的建议版本同步改为编译基线或更高版本。
- 1.20.1、1.20.4、1.21.1、1.21.4 的较新世界地图把 `MapElementRenderHandler.add(MapElementRenderer)` 改成 `add(ElementRenderer)`，即使保留旧绘制适配类，原二进制调用也会失败。新增零 Xaero 依赖的 `RendererRegistration`，按实际处理器选择能接收当前渲染器的公开注册方法；注册失败不重复尝试其他重载。
- 上述四个目标及 1.21.5 的较新世界地图把提示回调返回类型从 `CursorBox` 改为 `Tooltip`，旧编译桥接方法无法覆写新回调，原生方法直接返回 null。可选 `@Pseudo` Mixin 仅在原生提示为空且读者属于本模组时调用原类型化方法，返回原 `CursorBox`，继续使用 Xaero 原生绘制、菜单与隐藏规则。未安装世界地图时跳过注入。
- 1.20.1、1.20.4、1.20.6、1.21.1、1.21.4、1.21.5、1.21.8 的世界地图右键松开事件混用了 GUI 坐标与窗口坐标，缩放后会丢失双击记录。按照较高版本的实现统一坐标，保留移动容差、左键取消与延迟打开语义。

除各目标原有的编译基线外，还从官方 Modrinth 文件核对以下更新组合；1.20.6 和 26.x 使用仓库中已配置的对应版本。没有修改原编译依赖，因此产物继续兼容原依赖。

### BlueMap 修复与回归

原实现累加首尾闭合顶点的坐标后删除末点，却仍保留末点在累加和中的贡献，再以删除后的点数计算中心。例如 `(10,10)、(20,10)、(20,20)、(10,20)、(10,10)` 的中心被算为 `(17.5,17.5)`，正确结果为 `(15,15)`，导致 BlueMap marker 的位置偏移。

新增不依赖 BlueMap API 或 Minecraft 世界实例的 `BlueMapPolygonGeometry`，先过滤空顶点、去除重复闭合末点，再对实际用于构造 Shape 的顶点计算中心。全部 12 个工厂使用此处理；`src/` 和 `modern/src/` 保持相同算法与测试。

修复前从真实工厂抽取原几何方法，搭配实际 BlueMap 2.7.2 与 flow-math 1.0.3 JAR 执行，得到明确失败：`expected (15,15), got (17.5,17.5)`。修复后使用 JUnit 5.12.2，分别在旧版和现代版数据模型的实际编译产物上执行测试，两组均为 3/3 通过：

- 开放多边形和显式闭合多边形位置一致，输入列表不被修改。
- 空顶点与负坐标不会影响闭合识别或中心计算。
- 去除闭合末点后不足三个有效顶点时拒绝构造。

以上是源码、依赖接口与自动化回归检查结果，不代表已在 12 个版本中逐一完成游戏内联动测试。
