# 域名检测优化实施计划

**目标：** 落实用户选定的第 2、3、4 项：提前筛选 AABB、复用标题显示索引、增加空间索引。

**架构：** 在共享 geometry 包建立加载时构建的包围盒树，客户端与服务端分别把它放入既有域名快照。查询先按空间、等级和高度筛选，再按原有中心距离与文件顺序排序，最终继续使用原射线法。

**技术：** Java 17、现有 Gradle/Fabric 多版本构建、JUnit 5；不增加依赖。

## 设计与约束

- 选用包围盒树而非固定网格：超大域名仅保存一次，不因覆盖大量网格而膨胀；小集合直接扫描叶片。
- 每个检测器为一级域名及每组父域名建立索引；保留全局等级列表，用于原来的高度跳级规则。
- 空间查询清空调用方独享的候选列表，输出按距离升序排列的候选；距离相同时按原文件顺序。
- 查询与建树不修改域名 JSON，不替换射线法，不改变高度边界及父子层级语义。
- 显示索引单独保持“同名取最后一个”；已有名称查找保持“同名取第一个”。
- 索引在加载阶段构建完成后随快照整体发布；后台与主线程只读取已完成的树。
- 用户已允许测试；直接在 main 修改，不创建 worktree、不提交。

## 实施步骤

1. 新建 `src/main/java/areahint/geometry/AreaSpatialIndex.java`，必要时为 `AreaData` 增加已有缓存的只读访问方法。
2. 为共享空间查询编写固定种子等价性测试，覆盖边界、负坐标、高度、顺序、超大范围与并发读取；先确认测试能捕获缺失查询。
3. 修改 `AreaDetector`：加载时建立空间与显示索引，检测时仅对空间候选做射线判断，完整标题使用已有 Map 重载。
4. 修改 `AreaGamemodeResolver`：复用共享空间查询，保留原有效性过滤与层级停止规则。
5. 添加服务端层级与显示格式化回归，检查高度跳级、重叠域名稳定顺序和重名父域名显示。
6. 运行 JUnit、客户端与服务端编译/打包及差异检查；独立审查边界语义与复杂度。
