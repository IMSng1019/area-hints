# 阶段 6：第三方兼容隔离

> 前置：阶段 5 完成。**这一环的成本与构建框架无关**——依赖是否存在、API 是否还在，只能靠逐个版本落实。

## 目标

把 Xaero、BlueMap、VulkanMod 等第三方 API 引用从核心代码里彻底挤出去，改为**能力接口 + 每版本实现**，并让"该版本没有这个功能"成为明确、可降级的状态。

## 现状（动手前先核对）

- Xaero：约 23 处 import，分布约 9 个文件，集中在 `src/client/java/areahint/xaero/`（含 `minimap/`、`worldmap/` 两个子包）
- BlueMap：约 9 处 import，分布约 4 个文件，集中在 `src/main/java/areahint/map/`
- VulkanMod：`src/client/java/areahint/render/VulkanModCompat.java`
- ModMenu：`src/client/java/areahint/modmenu/AreasHintModMenuApi.java`（入口点，属构建期依赖）
- Xaero 依赖在 `gradle.properties` 里是**带 MC 版本的精确坐标**，各版本必须各自确认

## 任务

### Task 1：定义能力接口

**Files:**
- Create: `src/client/java/areahint/compat/ClientCapabilities.java`
- Create: `src/main/java/areahint/compat/ServerCapabilities.java`
- Create: 各能力的接口文件（如 `MinimapOverlayCapability`、`WorldMapOverlayCapability`、`MapMarkerCapability`）

**Step 1:** 接口方法用**本模组语义**命名（"在地图上叠加区域图形"），禁止出现 Xaero / BlueMap 的类型。
**Step 2:** 每个能力都要有"是否可用"的查询，使调用方能在不支持时走降级路径而不是崩溃。
**Step 3:** 接口放在 `src/`，**零第三方 import**。

### Task 2：把现有实现搬进 versions/

**Files:**
- 移动：`src/client/java/areahint/xaero/**` → `versions/<该能力最低支持版本>/src/client/java/areahint/xaero/**`
- 移动：`src/main/java/areahint/map/**` → `versions/<该能力最低支持版本>/src/main/java/areahint/map/**`

**Step 1:** **先汇报搬迁清单再动手**，因为搬迁会同时影响 mixin 配置、入口点、资源文件。
**Step 2:** 按"能力"整体搬迁，不要拆散半个包。
**Step 3:** 搬迁后 `src/` 只保留接口与调用点；调用点必须通过能力查询走降级。
**Step 4:** 每搬一个能力跑一次全版本构建。

### Task 3：能力注册与缺失降级

**Step 1:** 在客户端/服务端初始化时注册各能力实现；该版本没有对应依赖时注册"不可用"占位。
**Step 2:** 不可用时日志必须写明原因与影响的版本，**不允许静默失败**，也不允许抛异常中断启动。
**Step 3:** 配置面板中依赖能力的功能项，在能力不可用时显示为禁用并给出说明（按现有 UI 风格实现，不要新造控件）。
**Step 4:** 语言文件按仓库要求同步：**所有语言文件一起改**，不使用英文批量替换，不无故减少行数。

### Task 4：依赖声明按版本落地

**Files:**
- Modify: `stonecutter.gradle`
- Modify: `build.gradle`
- Modify: `src/main/resources/fabric.mod.json`

**Step 1:** 每个版本的 Xaero / BlueMap / ModMenu 坐标在构建脚本里按版本解析；查不到对应坐标的版本，**移除该依赖并在矩阵里标注缺失**。
**Step 2:** `fabric.mod.json` 的 `suggests` 内容按版本解析，禁止在 1.21 产物里写 1.20.4 的 Xaero 版本号。
**Step 3:** 缺失能力不得写成 `depends`，保持可选语义。

## 验收标准

- `src/` 下不再出现任何第三方 API import（Xaero / BlueMap / VulkanMod），残余必须逐条说明并给出处置计划。
- 每个能力都有"可用性查询 + 降级路径"，且降级路径可被验证（临时不装该 mod 启动不崩）。
- 所有已声明版本构建通过；缺依赖的版本被明确标注为"仅声明/实验性"。
- 语言文件全部同步且键集合一致。
- 汇报里给出：搬迁清单、能力清单与可用矩阵、每版本依赖缺失清单。

## 禁止事项

- 不在核心代码里保留"反射 + 字符串类名"的兜底调用作为长期方案（仅允许作为某个版本的临时实现，并在注释里写明原因与移除条件）。
- 不为通过构建而伪造依赖坐标。
- 不删减语言文件行数。
- 不写测试。
