# Fabric 后续版本适配计划

> 执行方式：主代理与子代理在 main 上按文件分工；用户已授权自主规划、实施与逐版本提交，无需 worktree。

**Goal:** 从已支持的 1.21.5 继续适配至官方最新稳定版，每个版本保留可追踪的构建、测试与提交记录。

**Architecture:** 延续 Stonecutter 共享源码与 versions 下版本专属平台实现，优先隔离渲染、GUI、网络和第三方 API 差异。26.x 的官方命名与 no-remap 构建单独处理，已有版本持续参与回归。

**Tech Stack:** Java 17/21/25、Fabric、Gradle、Stonecutter、JUnit 5。

## 执行顺序

1. 查询 Mojang manifest、Fabric 元数据和第三方发布信息，核实最新版；先完成已有依赖配置的 1.21.8，再推进 1.21.11、26.x 稳定发布节点。
2. 每个节点先启用构建并复现编译错误，读取对应游戏/API 的实际签名，按独立文件分派修复；保留原有域名行为与翻译。
3. 对逻辑变化补充有意义的回归测试；API 迁移通过目标编译、现有 JUnit、协议/通道校验、产物与 mixin 检查验证。
4. 运行目标 `:<version>:build` 与已支持版本回归，审查 diff，记录未进行的游戏内验证，提交 `Add Fabric <version> support`。
5. 每完成一版更新本文件的交接状态，然后继续下一版。当前工具没有手动清空/压缩上下文接口；使用此记录衔接自动压缩，避免丢失任务。
