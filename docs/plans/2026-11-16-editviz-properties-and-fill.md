# editviz 绘制与属性流程改进

**目标：** 移除框选和画笔的固定跨度限制，闭合选区笔／边界笔自动填充，并通过 easyadd 风格界面编辑域名属性、描述和副标题。

**架构：** 保留原有可撤销草稿及最终保存／审批入口。几何运算基于实际轮廓复杂度；只填充新增笔迹围出的空洞。属性复用现有向导控件，描述沿用联合域名共享的独立文件，副标题使用现有文字和颜色字段。域名和描述共同进入审批或带恢复日志的保存事务。

**技术：** Java 17/21/25、Fabric、Java2D Area、Gson、JUnit 5；旧版共享源码及 modern 源码同步维护。

## 实施步骤

1. 在几何与边界笔测试中复现超过 4096 格失败、闭合后留洞的问题；移除固定跨度检查，优化大矩形和重复栅格行处理。验证开放笔迹、已存在洞、父域名／同级域名及岸线约束。
2. 读取 easyadd 的完整向导流程，将属性表单改为分项入口、预设选择、上级域名列表、文本和长文本输入。保持取消返回、草稿和撤销行为。
3. 扩展草稿、客户端加载、服务端字段白名单及权限检查，支持副标题文字和颜色、描述编辑。沿用同联合域名共享描述的规则；明确提示共享影响。
4. 描述快照参与并发校验、审批重放及重新提交；直接保存和批准均确保域名／描述一起成功或一起回滚。测试事务失败及恢复。
5. 同步全部 11 种语言、命令文档及 modern 源码；运行针对性测试、12 个活跃版本构建、翻译及差异检查，独立审查后提交 main。

## 验收重点

- 大范围矩形不因跨度拒绝，真实顶点复杂度和世界坐标约束继续有效。
- 两种笔实际闭合时填充；开放笔迹不自动补线；边界笔填充遵守限制。
- 属性修改、描述和副标题在最终保存前只属于草稿，可取消、撤销及重做。
- 描述与域名的并发变更拒绝覆盖；失败不能出现只保存其中一项。
- 界面交互及真实联机审批需游戏内验证，编译和单元测试不能替代人工验收。
