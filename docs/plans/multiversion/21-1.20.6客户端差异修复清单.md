> ⚠ **绝不能只删 `@Override`**：那样 1.20.6 上会编译通过，但 `getScrollbarPositionX()` 变成一个没人调用的普通方法，滚动条会退回原版默认位置——**静默的行为回归**，比编译失败更危险。

### 4.3 建议改法：同一基类加桥接钩子（9 个子类只改名）

```java
    protected int compatScrollbarX() {
        return this.width - 6;
    }

    // 1.20.5 起原版滚动条钩子改名，用桥接方法把差异收在此处
    //? if >=1.20.5 {
    @Override protected int getScrollbarX() { return this.compatScrollbarX(); }
    //?} else {
    /*@Override protected int getScrollbarPositionX() { return this.compatScrollbarX(); }*/
    //?}
```

9 个子类：把方法签名行 `protected int getScrollbarPositionX()` 改成 `protected int compatScrollbarX()`（上一行的 `@Override` 与下面的方法体**一行不改**，`@Override` 仍然合法，因为基类声明了 `compatScrollbarX()`）。

**理由**：与 A 类同一批 9 个文件、同一个基类；1 处分支换 9 处分支。1.20.4 上行为等价（基类的 `getScrollbarPositionX()` 原样委托给子类覆写的钩子）。

如果要保持"子类直接覆写原版方法"的形态，每个子类写（注意这是多行块注释形态，取自 `06-阶段5` 第 38–47 行的仓库约定）：
