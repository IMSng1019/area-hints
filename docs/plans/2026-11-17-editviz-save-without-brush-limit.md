# editviz 取消主动保存与手动简化的边界笔限制

用户最初希望在出现“保存后的轮廓会越过边界笔限制”时自动收缩，随后明确选择直接取消这条限制。本次按最新要求实现，不增加自动收缩算法。

## 修改范围

- 两套 `BoundarySaveGuard.prepare` 改走无禁区参数的正常保存入口，保留原方法参数以兼容草稿调用。
- 两套 `VizEditScreen.simplifyBoundary` 改走无禁区的主动简化，移除该操作后的边界笔限制拦截。
- 边界笔实际绘制、松笔自动优化、旧边保护和限制线记忆继续按原规则工作。
- 保存缓存、草稿副本、撤销顺序、客户端和服务端扩张／缩小权限、0.1 格精度、1 格偏移及单环合法性校验沿用既有流程。
- 更新 `COMMAND_USAGE.md` 中主动操作仍受边界笔限制的旧说明；无需修改翻译文案。

## 回归验证

- 原右边界 `10.06`、禁区从 `10.06` 开始：主动保存应成功量化为 `10.1`，输入草稿不变。
- 带边界笔限制的主动保存结果与普通保存一致。
- 自动绘制优化继续保护局部阶梯边界和海岸线；真实洞仍拒绝保存。
- 新保存期望先在旧实现中确认失败：精度案例抛出 `save_conflict`，主动简化结果与普通保存不一致。修改生产代码后重新验证。
- 实际 Java 17、21、25 中，保存守卫 6 项和边界笔 30 项均通过；modern 独立编译验证同样通过。
- 完整命令：`.\gradlew.bat --gradle-user-home .gradle-home '-Dorg.gradle.java.home=J:/mc/jdk25' '-Pmod_version=4.8.5-editviz.3' build --offline --no-parallel --no-daemon --console=plain`。12 个版本构建成功，耗时 1 分 31 秒，共 2462 项测试，零失败、错误或跳过。
- 核验 1.20.1 产物字节码，`BoundarySaveGuard.prepare` 实际调用单参数、无禁区的保存方法；两套对应几何源码和测试一致，差异检查及独立审查通过。
- 未替换或重启用户运行中的游戏；安装新客户端包后才能进行本机游戏内复测。
