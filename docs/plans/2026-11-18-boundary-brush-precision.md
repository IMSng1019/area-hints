# 边界笔受约束裁剪的浮点伪洞修复

用户反馈快速涂抹边界后出现不同几何错误，需要反复涂抹。最近一次游戏日志加载的是 `4.8.5-editviz.3`，不能归因于未加载此前修复；检查时没有正在打开的 Minecraft 窗口，未获得现场草稿或完整错误集合。

## 已复现的根因

边界笔先从完整选区减去旧域名、裁剪新增部分，再并回旧域名。同一条小数斜边被反复求交后，会生成极小但非零的伪洞或伪岛。此前的恢复只适用于硬禁区和自然禁区均为空，带父域名或同级域名限制时仍会出错。

- 旧域名为 `(4.8,-8.5)、(-22,3.4)、(14.8,-14.8)`，父域名为矩形 `(-50,-50)-(-9,50)`，笔宽 10，绘制 `(0,-6)`。整笔被父域名挡住，却产生约 `9.47e-30` 平方格伪洞。
- 旧域名为 `(-18.8,26.3)、(-10.3,14.3)、(-4.2,0.7)`，父域名为矩形 `(-50,-50)-(0,50)`，笔宽 5，经过 `(-16,7)、(16,-7)`。产生约 `1.18e-30` 平方格伪洞；旧域名完整位于父域名内。

两项正式回归在修改生产代码前均准确失败于 `geometry_holes`。第二例将父域名限制换为右侧同级域名，同样纳入回归。

## 修复方式

- 正常绘制保留原算法。仅当拆分并回的结果为非法多环时，尝试从完整选区直接裁剪父域名、同级域名和自然禁区，再并回旧域名。
- 候选必须为合法单环、没有旧面积损失，并通过包含历史硬禁区和自然禁区的完整检查。无法证明安全时保留原结果，不丢弃任何真实小区域，也不按面积阈值忽略洞。
- 原始笔迹完全被挡住且填充前没有正面积内环时，直接保留旧形状，避免无效并集继续切割旧边。父域名外的闭环仍可以填充其内部，单独增加用例保护这一行为。
- 根目录与 `modern` 的实现、测试完全同步；不改变 JSON、翻译或 Minecraft 接口。

## 验证

- 边界笔 35 项测试在实际 Java 17、21、25 分别通过，覆盖父边界、同级边界、被完全阻挡的笔画、外围闭合填充和真实微小同级域名孔洞。
- 独立审查对基线 `033e7d6` 与实际修复源码运行 5000 组、每组 3 点的随机对照；Java 17、25 各改善 190 次非法结果，未出现合法变非法、额外旧面积损失或额外禁区越界。
- 构建使用独立版本标识 `4.8.5-editviz.4`，避免与用户已经加载的修复包混淆。
- 完整构建命令：`.\gradlew.bat --gradle-user-home .gradle-home '-Dorg.gradle.java.home=J:/mc/jdk25' '-Pmod_version=4.8.5-editviz.4' build --offline --no-parallel --no-daemon --console=plain`。沙箱内构建被 Loom 系统临时文件访问权限阻止，获准在沙箱外离线重跑后，16 个活跃版本全部成功，耗时 1 分 42 秒。
- 按活跃版本汇总 JUnit XML：3350 项测试，失败、错误、跳过均为零；逐个确认 16 份 JAR 的版本字段为 `4.8.5-editviz.4` 且包含本次恢复方法。两套源码／测试内容一致，`git diff --check` 通过。

## 范围与后续证据

本次修复已复现的裁剪伪洞、伪岛，不宣称消除全部 Java2D 浮点误差；非法单环自交不进入本次恢复。没有重启游戏、替换用户安装包或修改现场域名数据，仍需加载新包实机复测。

另外发现独立的岸线采样预算问题：真实 `BoundaryTerrainCache` 每 tick 最多读取 8 个瓦片，宽 4 的 `(-0.2,-100)→(-0.2,100)` 快速笔画可能跳过中途未知岸线，终点重试也不补读中段。该复现的几何校验通过，尚未证明与本次报错相同，未混入本次裁剪修复。
