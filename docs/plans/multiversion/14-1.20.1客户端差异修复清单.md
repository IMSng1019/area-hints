## 三、A 组：`Screen.renderBackground`（4 处 / 4 文件）

### 3.1 报错原文（探测日志第 98 行，其余 3 处同形）

```
...\generated\stonecutter\client\java\areahint\commandui\CommandUiScreen.java:103: 错误: 无法将类 Screen中的方法 renderBackground应用到给定类型;
        this.renderBackground(context, mouseX, mouseY, delta);
  需要: DrawContext
  找到:    DrawContext,int,int,float
  原因: 实际参数列表和形式参数列表长度不同
```

### 3.2 API 差异本质：同名方法签名收窄（1 参 → 4 参）

javap 实测（1.20.1 与 1.20.4 的 `net.minecraft.client.gui.screen.Screen`）：

| 版本 | `renderBackground` 重载 | `renderBackgroundTexture` |
|---|---|---|
| 1.20.1 | `public void renderBackground(DrawContext)` | 有 |
| 1.20.4 | `public void renderBackground(DrawContext, int, int, float)` | 有 |
| 1.20.6 / 1.21.1 | `public void renderBackground(DrawContext, int, int, float)` | 有（另有静态 8 参重载，与本处无关） |

补充实测（用于确认这不是「同一逻辑的两种入口」而是真差异）：

- 1.20.4 的 `Screen` **没有** 1 参 `renderBackground`，其父类链 `AbstractParentElement` / `Element` / `Drawable` / `ContainerWidget` 也都没有 → 17 号文档第 191/196 行「1.20.4 两个重载都在」不成立。
- **两版的方法体逐字节等价**：1.20.1 的 1 参版本 = `if (client.world != null) context.fillGradient(0, 0, width, height, -1072689136, -804253680); else renderBackgroundTexture(context)`；1.20.4 的 4 参版本 = `if (world != null) renderInGameBackground(context); else renderBackgroundTexture(context)`，而 `renderInGameBackground` 体就是同一句 `fillGradient(0,0,width,height,-1072689136,-804253680)`；4 参版本里 `mouseX/mouseY/delta` **未被使用**。
- 结论：**分支后两版视觉行为不变**，不存在「1.20.4 上少画了模糊/遮罩」的风险。

### 3.3 建议改法（以 `CommandUiScreen.java:103` 为例，其余 3 处同形）

```java
        // 1.20.2 起 renderBackground 改为 4 参、1 参重载移除，故按版本分支
        //? if >=1.20.2 {
        this.renderBackground(context, mouseX, mouseY, delta);
        //?} else {
        /*this.renderBackground(context);*/
        //?}
```

> 写法依据 `06-阶段5-机械改名与条件注释.md` 第 38–47 行的仓库约定：**非活跃分支写成块注释**（当前 `stonecutter.active "1.20.4"`），条件链最后一个分支不带花括号闭合。仓库内目前 `//?` 命中 0（`12-目录契约.md` 附录 A-4），**这是全仓库第一处条件注释，必须先在一处上构建验证语法**（见第八节 U1）。

**理由**：两版无共同签名，属「单方法内 1 条语句」差异 → 条件注释（规则 3）；类本身是屏幕 UI，禁止搬进 `versions/`（规则 4）。

## 四、B 组：`ElementListWidget` 构造器参数个数（9 处 / 9 文件）

### 4.1 报错原文（探测日志第 115 行，其余 8 处同形）

```
...\AreasHintConfigScreen.java:589: 错误: 无法将类 ElementListWidget<E>中的构造器 ElementListWidget应用到给定类型;
            super(client, width, bottom - top, top, 24);
  需要: MinecraftClient,int,int,int,int,int
  找到:    MinecraftClient,int,int,int,int
  原因: 实际参数列表和形式参数列表长度不同
```

### 4.2 API 差异本质：构造器 5 参 → 6 参，且父类从 `ContainerWidget` 换回 `AbstractParentElement`

javap 实测：

| 版本 | 构造器 | 类声明 |
|---|---|---|
| 1.20.1 | `EntryListWidget(MinecraftClient, int, int, int, int, int)` | `extends AbstractParentElement` |
| 1.20.4 / 1.20.6 / 1.21.1 | `EntryListWidget(MinecraftClient, int, int, int, int)` | `extends ContainerWidget` |

参数语义由**字节码**确认（不是猜的）：

- 1.20.1 构造器把 6 个参数依次写入 `client / width / height / top / bottom / itemHeight` 六个字段 → 即 `(client, width, height, top, bottom, itemHeight)`，`top`/`bottom` 是列表区的**绝对 y 坐标**。
- 1.20.4 构造器把 `(int x=0, y=第4参, width=第2参, height=第3参)` 交给父类 `ContainerWidget.<init>`，再写 `client` 与 `itemHeight` → 即 `(client, width, height, y, itemHeight)`，`bottom = y + height`。

**等价映射**：1.20.4 的 `super(client, W, H, y, itemH)` ≡ 1.20.1 的 `super(client, W, H, y, y + H, itemH)`。

### 4.3 建议改法（两种形状，按当前实参写法分）

形状 ①：7 处（实参里已有 `bottom` 形参，且第 3 参是 `bottom - top`）→ 1.20.1 直接补 `bottom`：

```java
        // 1.20.2 起 EntryListWidget 构造器由 6 参（top,bottom）改为 5 参（y）
        //? if >=1.20.2 {
        super(client, width, bottom - top, top, 24);
        //?} else {
        /*super(client, width, bottom - top, top, bottom, 24);*/
        //?}
```

形状 ②：2 处（soundevent，实参是 `height` + `top`，没有现成 `bottom`）→ 补 `top + height`：

```java
        // 1.20.2 起 EntryListWidget 构造器改为 5 参（y），1.20.1 需要 top/bottom 两个绝对坐标
        //? if >=1.20.2 {
        super(client, width, height, top, ROW_HEIGHT);
        //?} else {
        /*super(client, width, height, top, top + height, ROW_HEIGHT);*/
        //?}
```

**理由**：同一构造器在不同版本参数个数不同，属「单方法内 1 条语句」差异 → 条件注释；9 个子类都是屏幕内部类，禁止搬进 `versions/`（规则 4）。

**备选收口方案（若 Lead 认为 9 处太散）**：在 `src/client/java/areahint/gui/` 新增一个兼容基类，把**唯一一个**条件块收进它的 5 参构造器（1.20.1 侧转成 `(client,width,height,y,y+height,itemHeight)`），9 个子类只改 `extends` 与 import、`super(...)` 实参**一行都不用动**。总行数更少、分支只有 1 处；代价是多一个新类。两者都在规则 3 允许范围内，本清单默认推荐就地条件注释（零新概念）。

## 五、C 组：`Text` 的 JSON 序列化入口（1 处 / 1 文件）

### 5.1 报错原文（探测日志第 84 行）

```
...\description\BookDescriptionScreenUtil.java:40: 错误: 找不到符号
            pages.add(NbtString.of(Text.Serialization.toJsonString(Text.literal(page))));
                                       ^
  符号:   变量 Serialization
  位置:   接口 Text
```

### 5.2 API 差异本质：序列化入口整类改名/移位

javap 实测（`net.minecraft.text.Text` 的两个内部类）：

| 版本 | 可用入口 | 说明 |
|---|---|---|

```java
            pages.add(NbtString.of(Text.Serialization.toJsonString(Text.literal(page))));

            /*pages.add(NbtString.of(Text.Serializer.toJson(Text.literal(page))));*/
            //?}
```

**理由**：单方法内 1 条语句的机械改名 → 条件注释；`BookDescriptionScreenUtil` 仍是 1.20.x 形态的 UI 工具类，本批不需要机制 ②。

## 六、D 组：`ClickableWidget.setDimensionsAndPosition`（2 处 / 2 文件）

### 6.1 报错原文（探测日志第 131 行）

```
...\SoundEventCategoryScreen.java:116: 错误: 找不到符号
                this.button.setDimensionsAndPosition(entryWidth, BUTTON_HEIGHT, x, y + 3);
                           ^
  符号:   方法 setDimensionsAndPosition(int,int,int,int)
  位置:   类型为ButtonWidget的变量 button
```

### 6.2 API 差异本质：1.20.1 缺少「一步定位 + 定尺寸」的便捷方法

javap 实测（`ClickableWidget` / `Widget`）：

| 版本 | `setWidth` | `setHeight` | `setDimensions` | `setDimensionsAndPosition` | `Widget.setPosition(int,int)` |
|---|---|---|---|---|---|
| 1.20.1 | 有 | **无** | **无** | **无** | 有（default） |
| 1.20.4 / 1.20.6 / 1.21.1 | 有 | 有 | 有 | 有 | 有（default） |

语义（字节码）：1.20.4 的 `setDimensionsAndPosition(w,h,x,y)` = `setDimensions(w,h)` 后再 `setPosition(x,y)`；`setDimensions` 只是写 `width`/`height` 两个字段。因此

**`setWidth(entryWidth)` + `setPosition(x, y + k)` 与 `setDimensionsAndPosition(entryWidth, BUTTON_HEIGHT, x, y + k)` 完全等价**——因为按钮创建时已通过 `.dimensions(0, 0, 200, BUTTON_HEIGHT)` 把高度设成 `BUTTON_HEIGHT`，这里只是重申同一个高度值。

### 6.3 建议改法（两版通用，无需任何版本分支）

```java
                // 1.20.1 没有 setDimensionsAndPosition，等价拆成 setWidth + setPosition（高度构造时已定）
                this.button.setWidth(entryWidth);
                this.button.setPosition(x, y + 3);
```

**理由**：`setWidth` 与 `Widget.setPosition(int,int)` 在 1.20.1 / 1.20.4 / 1.20.6 / 1.21.1 四版都存在（javap 实测），是一次性消掉版本差异的写法，比条件注释更省；因此既不用条件注释，也不用机制 ②。

### 6.4 逐处清单

| # | 文件（相对 `src/client/java/areahint/`） | 行 | 当前写法 | 改后 |
|---|---|---|---|---|
| D1 | `soundevent/SoundEventCategoryScreen.java` | 116 | `setDimensionsAndPosition(entryWidth, BUTTON_HEIGHT, x, y + 3)` | `setWidth(entryWidth);` + `setPosition(x, y + 3);` |
| D2 | `soundevent/SoundEventListScreen.java` | 172 | `setDimensionsAndPosition(entryWidth, BUTTON_HEIGHT, x, y + 4)` | `setWidth(entryWidth);` + `setPosition(x, y + 4);` |

> 注意：D 的改法会让 1.20.4 侧的那两个 `Entry` 内部类字节码从「1 次 invokevirtual」变成「2 次」，**行为不变但 class 字节不同**。D1 基线口径是 `jar tf` 逐条一致（456 条），本次仍满足；如需 1.20.4 class 字节也完全不变，就把 D 也写成条件注释（1.20.4 分支保留 `setDimensionsAndPosition`），代价是多 2 个条件块。
