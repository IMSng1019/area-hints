# 多版本兼容分阶段提示词

> 用一句话概括：**Stonecutter 管构建编排与机械改名，NetworkCompat 管网络层这一处深断点，物理隔离让 src/ 里绝大多数文件永远不出现条件块。**

本目录把整个多版本改造拆成 9 个阶段，每个阶段一个可直接复制使用的提示词文件。
**所有工作都在 main 分支上进行**：不新建分支、不建 worktree、不写测试、不提交。

## 使用方式

1. 先读 `20-交接说明-下一会话从哪开始.md`，再读 `00-总纲与约定.md`（版本清单、D1–D6 决策、硬性禁止项都在总纲里）。
2. 按编号顺序执行 `01` → `08`，**一次只执行一个阶段**。
3. 每个阶段结束后必须向我汇报"产出物 + 构建结果 + 未决项"，等我明确说"进入下一阶段"再继续。
4. 任何阶段发现前一阶段的结论不成立（例如某版本依赖根本不存在），立刻停下汇报，不要自行降级方案。

## 硬性禁止项（每个阶段都适用）

- 不新增任何测试文件（我会自己进游戏测试）。
- 不创建分支、不创建 worktree、不执行 git commit。
- 不在 web 端点任何东西；所有构建用 Gradle 命令在本地验证。
- 不删除或改写现有功能的行为；本系列只做"让它能在多个版本上编译并运行"，不夹带功能改动。
- 不改动 `build/`、`run/` 等生成目录。
- 三层分工不能混用：**能放 `versions/` 的整块差异，不要用条件注释硬凑**；能用一行条件注释解决的，不要新建版本文件。
- **`versions/<v>/${Q} 里不得出现与共享 `src/` 同名的类**——实测会直接报 `错误: 类重复`（机制 ① 已被否决）。
- **1.20.4 是常驻基线**（D1）：任何改动后都要与基线 `jar tf`（456 条）逐条比对。
- 第三方依赖必须按版本解析（D2），不得跨版本沿用。
