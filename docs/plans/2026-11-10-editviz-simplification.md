# editviz 坐标精度与边界简化实施计划

**目标：** 新生成坐标按 0.1 格量化，简化后轮廓相对操作前原始轮廓的偏移最多 0.5 格，量化误差计入该限额。

**架构：** 保留现有几何验证和服务端权限、审批流程；新增仅用于客户端草稿的几何优化入口。绘制结束时只优化新增边界，保留旧边及交点的原始精度；显式“简化边界”按钮处理当前完整边界。优化直接写入可撤销草稿，使画布、审批预览和保存值一致。

**技术：** Java 17、Java2D Area、多版本 Fabric Screen、现有 11 种语言与 Gradle 验证。

## 实施步骤

1. 在 `src/main/java/areahint/vizedit/geometry/` 实现有误差上限、旧边保护和复杂度限制的轮廓优化。不得改变 `validate`、`union`、`subtract` 的既有语义；无法安全简化则保留原形状。
2. 在 `src/client/java/areahint/vizedit/VizEditScreen.java` 接入笔画完成、魔棒和显式按钮，复用草稿历史；按实际面积差检查界面权限，服务端继续重新检查。显示简化前后点数。
3. 更新全部语言的按钮、提示、结果文本，以及 `COMMAND_USAGE.md`。
4. 按用户要求不新增测试文件；运行现有测试、五版本构建、翻译键检查及 `git diff --check`，执行独立代码审查。

## 验收要点

- 长斜线与椭圆的阶梯顶点减少，保存后重新打开与简化预览一致。
- 负坐标、大坐标和旧小数斜边不会因普通属性编辑被整体量化；新增与旧边交点保留旧边所需精度。
- 显式简化可撤销、重做，状态提示显示前后点数；只读、失效、等待提交时不可操作。
- 洞、不连通及自交不能被简化悄悄修复；细窄连接保留，不能安全量化的边界保留原样。
- 缺少扩张或缩小权限时，不额外引入需要该权限的几何变化。
- 两种画布、审批草稿、鼠标释放和离开画布的交互需游戏内人工验收；构建通过不代表这些项目已完成。

- `python -X utf8 tools/check_vizedit_translations.py`：11 种语言均有 2567 个键、88 个编辑器键，占位符与静态引用一致。
- `git -c core.safecrlf=false diff --check`：通过。
- 独立代码审查覆盖轮廓误差、量化、旧边共线重叠保护、权限、草稿历史、窗口重建和五版本 Xaero 浮层生命周期，未留下阻塞问题。
